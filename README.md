# 🌲🌊 숲으로 바다로 — 차박·캠핑 편의시설 지도

> **"도시를 떠나 자연을 만끽하고 싶은 여러분 — 떠나고 싶은 곳을 입력해 보세요. 필요한 정보는 다 알려드릴게요."**

떠나고 싶은 곳을 검색하면 주변 **화장실·야영장·해수욕장·주차장**과 개방시간·날씨·안전정보를 지도로 보여주고,
AI(RAG)가 차박/캠핑에 적합한 곳을 **데이터 근거와 함께** 추천하는 웹 서비스.
첫 화면은 검색창 중심(구글 홈 스타일), 지도는 버튼/추천 시 진입.

> ⚠️ **포지셔닝**: "노지 캠핑 장소 추천"이 아니라 "사용자가 고른 지점의 공공 편의시설 정보 제공". 합법 야영장을 함께 안내.

**데이터**: 전국 공공데이터 **11종 약 8.7만 건** (화장실 6만 · 공영주차장 1.7만 · 전기차 · 야영장 · 문화축제 …).
**차별점**: 둔치주차장 정부 공인 **침수위험등급** 신호등 마커 · 전기차 **실시간** 급속/완속 가용 · 제주 월파 **CCTV 실시간 영상**.

## 🛠️ 기술 스택 — 이게 다 뭐냐면

> 처음 보는 용어가 많아도 괜찮습니다. **"무엇을 하는 도구인지"** 감만 잡으면 됩니다.

**① 데이터를 모으는 도구**
- **공공데이터포털 표준 API** — 정부(행정안전부 등)가 무료로 개방한 데이터를, 인터넷 주소로 요청하면 JSON(구조화된 텍스트)으로 돌려줍니다. 화장실·주차장·축제 위치가 전부 여기서 옵니다.
- **카카오 지오코딩 API** — `"제주시 첨단로 242"` 같은 **주소를 위도·경도 좌표로 변환**합니다. 지도에 점을 찍으려면 좌표가 꼭 필요하거든요.

**② 서비스를 돌리는 서버 (백엔드)**
- **Python + FastAPI** — 파이썬으로 웹 서버를 만드는 도구. 브라우저가 *"지금 화면에 보이는 영역의 화장실 데이터 줘"* 라고 요청하면, 데이터를 찾아 돌려주는 역할. 배우기 쉽고 빠릅니다.
- **SQLite** — **파일 하나(`facilities.db`)로 된 초경량 데이터베이스**. 8.7만 건을 여기 담아두고 순식간에 검색합니다. 별도 설치가 필요 없어서 팀 프로젝트에 딱입니다.

**③ 사용자가 보는 화면 (프론트엔드)**
- **HTML / CSS / JavaScript** — 웹페이지의 뼈대(HTML)·꾸밈(CSS)·동작(JS). 프레임워크 없이 순수하게 씁니다.
- **카카오맵 JavaScript SDK** — 웹페이지에 **지도·마커·로드뷰**를 띄우는 카카오 공식 도구.
- **HLS (hls.js)** — 제주 월파 CCTV의 실시간 영상(`.m3u8`)을 브라우저에서 재생하는 스트리밍 방식.

**④ AI 추천 (RAG)**
- **RAG (검색증강생성)** — GPT가 아무렇게나 답하지 않고, **우리 데이터·규정 문서를 먼저 찾아서(검색) 그걸 근거로 답(생성)**하게 하는 방법. *"여기 취사 돼요?"* 에 실제 법령을 인용해 답할 수 있는 게 이 덕분입니다.
- **sentence-transformers** — 문장을 숫자 벡터로 바꾸는 AI 모델(임베딩). 의미가 비슷한 문장은 벡터도 비슷해져서, "비슷한 내용 찾기"가 가능해집니다.
- **FAISS** — 그 벡터들 중 **질문과 가장 비슷한 문서를 빠르게 찾아주는** 검색 엔진.
- **GPT mini** — 찾아온 근거를 사람 말로 정리해 **최종 답변을 만드는** 생성 모델.

**⑤ 배포·인프라 (GCP, 구글 클라우드)**
- **Cloud Run** — 우리가 만든 서버를 구글 클라우드에 올려 **인터넷 어디서든 접속 가능**하게 합니다. 아무도 안 쓰면 요금 0원.
- **Cloud Build** — 코드를 컨테이너(도커 이미지)로 **자동으로 빌드**해주는 도구.

## 👥 팀 & 역할 (4인) — 누가 뭘 만드나

**전체 흐름 한눈에**: `[D] 데이터 준비 → [B] AI가 데이터로 답할 준비 → [C] 질문 받아 추천하는 서버 → [A] 사용자가 보는 화면`
데이터·CI는 이미 완료 상태라 **A·B·C 모두 바로 개발 시작 가능**합니다.

### 🎨 A — 프론트엔드 & 통합 (`frontend/`)
사용자가 실제로 **보고 클릭하는 화면**을 만듭니다.
- 검색창 랜딩 화면, 지도에 마커 찍기, 마커 클릭 시 상세 카드 띄우기, 로드뷰·CCTV 영상 재생
- 채팅 답변이 오면 지도를 해당 지역으로 이동시키고 관련 레이어(화장실·주차장 등) 켜기
- **쓰는 기술**: HTML/CSS/JavaScript, 카카오맵 SDK

### 🤖 B — AI / RAG (`rag/`)
GPT가 **우리 데이터를 근거로 똑똑하게 답하도록** 밑작업을 합니다.
- 지식베이스 준비: 캠핑 규정·야영장 소개·축제 정보(`data/raw/*.jsonl`)를 모아서
- 임베딩(sentence-transformers) → FAISS에 저장 → *"질문과 비슷한 문서 찾기"* 함수 제공
- 이 검색 함수를 C의 채팅 API와 연결 (인터페이스는 C와 **먼저 합의**하고 시작)
- **쓰는 기술**: 파이썬, sentence-transformers, FAISS

### ⚙️ C — 추천 백엔드 & 배포 (`backend/`, `Dockerfile`)
질문을 받아 **점수를 매겨 추천**하고, 서비스를 인터넷에 올립니다.
- `/api/chat`: 질문 분석(지역·날짜·조건) → 주차장·화장실 근접도 **점수화** → B의 RAG 근거 + GPT로 답변 생성
- `/api/beach-timing`: 해수욕장 파고·수온 등 실시간 정보
- 완성된 서버를 도커로 포장해 **Cloud Run에 배포**
- **쓰는 기술**: 파이썬, FastAPI, GCP

### 🗂️ D — 데이터 · 일정 · 발표 (`data_pipeline/`, `docs/`) — *현재 나*
서비스의 **연료(데이터)**를 만들고 팀 진행을 관리합니다.
- 공공 API 수집 → 좌표 변환 → `facilities.db` 빌드 **(완료)**
- 발표 자료·데모 시나리오 준비, 일정 점검(스탠드업), 키·GitHub 초대 관리
- **쓰는 기술**: 파이썬, 공공데이터 API

> **협업 방식**: B와 C는 짝(RAG ↔ 챗봇 API 연결)이라 인터페이스를 먼저 맞추고 시작합니다.

**꼭 읽을 문서**: 협업 규칙 [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md) · 추천 설계(B·C 필독) [docs/recommendation-pipeline.md](docs/recommendation-pipeline.md) · 데이터 전략 [docs/data-management.md](docs/data-management.md) · 일자별 할 일 [docs/TODO.md](docs/TODO.md)

> 🤖 **CI (자동 코드 검사)**: `main`에 push하거나 PR을 올릴 때마다 GitHub가 자동으로 돌립니다 — 문법 오류, 백엔드 정상 로드, 소스에 키를 실수로 넣었는지 검사. 결과는 레포 **Actions 탭**에서 초록 ✅ / 빨강 ❌ 로 확인.
