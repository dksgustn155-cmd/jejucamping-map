## 2. 데이터 스키마

**`ordinances.jsonl`** (전국 조례, 한 줄 = 조례 1건)
```json
{"id":"ordin:2046025", "지자체":"전남광주통합특별시 담양군",
 "조례명":"담양군 오토캠핑장 관리 및 운영에 관한 조례",
 "분야":"관광", "시행일":"20250919", "규제형":true, "원문":"제1조(목적)…전문…"}
```
- `규제형`: 본문에 취사·차박·금지·과태료가 있으면 `true`(206건). 등록·지원형 조례는 `false`.

**`regulations.jsonl`** (구조화, `type`으로 구분)
```json
{"type":"law","법령명":"자연공원법","조항":"제27·86조","장소유형":"국립공원",
 "요약":"…","위반시":"야영 50만·취사 20만원 이하","출처":"…","원문확보":true}
{"type":"qa","q":"한라산 취사 돼요?","a":"안 됩니다…","근거":"자연공원법 제27조"}
```

## 3. 사용법 (로드 예시)

```python
import json

# 전국 조례 로드
ords = [json.loads(l) for l in open("data/raw/ordinances.jsonl", encoding="utf-8")]

# 특정 지역 조례만 (region-aware 검색의 핵심)
def ordinances_of(region: str):
    return [o for o in ords if region in o["지자체"]]

damyang = ordinances_of("담양")     # 담양군 오토캠핑장 조례
print(damyang[0]["원문"][:300])

# 국가법 원문
natl = open("docs/규정원문/자연공원법.txt", encoding="utf-8").read()
```

## 4. RAG 활용 방안 (B·C 필독)

**임베딩 대상 (3층 구조)**
1. `regulations.jsonl` — 요약·Q&A (구어체 질문에 검색 잘 됨, **1차 검색**)
2. `data/raw/ordinances.jsonl` — 전국 조례 원문 (지역 특화, **지역 매칭 시**)
3. `docs/규정원문/*.txt` — 국가법 원문 (정확 인용·폴백)

**⭐ 지역 인지(region-aware) 검색 — 가장 중요**
조례는 *그 지자체에서만* 유효합니다. 챗 흐름:
```
질문 "담양 계곡에서 취사 돼?"
  → region 파싱: "담양"  (추천 파이프라인 조건파싱 재사용)
  → ① 담양군 조례 검색 (ordinances.jsonl, 지자체 필터)
  → ② 국가법 검색 (regulations.jsonl / 원문 txt) — 항상 폴백
  → gpt-5-mini: 검색된 근거만 인용해 답변 (환각 방지)
```
지역 조례가 없으면 **국가법만으로 답변**(국가법은 전국 적용).

**청킹**: 조례·국가법 모두 **조문(제N조) 단위**로 분할해 임베딩 → 인용 단위가 조문이 됨.

**답변 규칙 (신뢰성·프레이밍)**
- 검색된 **법령명·조항·과태료·출처**를 반드시 인용 (근거 없으면 "확인 필요")
- 금지만 말하지 말고 **합법 대안**(등록 야영장·허용 지점) 함께 안내
- 프레이밍: "차박하세요" ❌ → "이 지점 주변 편의시설·규정 안내" ✅

## 5. ⚠️ 주의사항

- **발표 슬라이드에 "2026.7 기준" 표기** — 법령·과태료는 개정될 수 있음

## 8. ⚠️ "특정 주소는 취사가 어렵다"에 대응되나? (중요)

**부분적으로 가능하며, 좌표 데이터와 결합해야 완성됩니다.** 데이터를 확인한 결과:

| 질문 유형 | 대응 | 근거 |
|---|---|---|
| *"공영주차장/국립공원/해수욕장에서 취사 돼?"* (**장소 유형**) | ✅ 바로 답변 | 국가법·조례 원문에 유형별 규칙·과태료 있음 |
| *"담양에 등록된 오토캠핑장 어디야?"* (**조례 명시 시설**) | ✅ 답변 | 조례에 시설 주소 명시(금성면 새덕굴길) |
| *"이 좌표(지점)가 취사 금지야?"* (**임의 지점**) | 🟡 좌표 대조 필요 | 그 지점이 하천구역/공원/해변 **경계 안**인지 판단 → 해당 규칙 적용 |
| *"○○로 12번지가 금지구역 고시됐어?"* (**지번 단위 고시**) | ❌ 대부분 미보유 | 세부 금지구역 "지정·고시(告示)"는 조례와 별개 문서, 우리 데이터에 없음 |

**핵심**: 조례·법령 텍스트는 *"해수욕장/공원/하천에서 취사 금지"* 처럼 **장소 유형 수준**까지만 답합니다. *"이 주소가 금지인가"* 는 텍스트만으론 안 되고, **그 지점이 어떤 장소유형에 속하는지**를 판단해야 합니다.

> ✅ **(7/7 해결) 국립공원은 좌표 판정 구현 완료** — 아래 9절 GIS 참고. 백록담 좌표를 주면 "한라산국립공원 → 자연공원법 제27조"가 자동으로 나옵니다.

**→ 우리 서비스의 강점으로 해결**: 우리는 이미 시설·지점의 **좌표 데이터**를 가지고 있으므로,
1. 사용자가 찍은 지점의 좌표 → 근처가 하천/해수욕장/공원/국립공원인지 판단(향후 경계 데이터 추가 시 정밀)
2. 해당 장소유형의 규칙을 RAG로 인용
→ *"이 지점은 하천 둔치라 지정지역이면 취사가 제한될 수 있고(하천법 제46조), 호우 시 침수 위험이 있어요"* 식 답변 가능.
단, **지번 단위 확정 금지구역**은 지자체 고시가 필요하므로, 답변은 *"제한될 수 있으니 현장 안내판·지자체 확인 권장"* 으로 **단정 대신 안내**하는 것이 안전합니다(오답 리스크·프레이밍).

## 9. GIS 경계 판정 + 고시 자동수집 (7/7 구축)

### 좌표 → 규제구역 판정 (`/api/zone-check`) — 자연공원 154개
- **데이터**: 국립 23(`national_parks.geojson`, 공공데이터포털 SHP) + **도립 99·군립 32**(`natural_parks_vworld.geojson`, 브이월드 WFS) — 셋 다 **자연공원법 동일 적용**(제27조 야영·취사·주차 금지)
- **API**: `GET /api/zone-check?lat=33.3617&lon=126.5292` → `{"zone":"한라산","kind":"국립공원","rules":["자연공원법 제27조 …"]}` (순수 파이썬 point-in-polygon)
- **검증**: 백록담→한라산 국립 / 마이산·모악산→도립 / 시청→밖 ✅
- **챗 연동(C)**: 사용자가 지점을 찍거나 지역을 말하면 zone-check → 공원 안이면 규정 인용을 답변에 포함
- **스크립트**: `build_gis_boundaries.py`(국립 변환) · `download_vworld_boundaries.py`(도립·군립, 재실행형). 브이월드 개발키 `.env`의 `VWORLD_KEY`(만료 2027-01-08)
- **확장 여지**: 브이월드에 산림보호구역(lt_c_uf151)·습지보호지역(lt_c_um901)·하천망(lt_c_wkmstrm)·도시자연공원구역(lt_c_uq162) 레이어 확인됨 — 필요 시 같은 방식 추가
- ⚠️ 국립 원본이 '경계버퍼'(약간 넓음) — 안내 용도론 보수적이라 안전. 답변은 "안내 목적" 프레이밍 유지

### 고시 자동 수집 (`download_notices_api.py`) — 재실행형 자동화
- 국가법령정보 오픈API에서 **행정규칙(target=admrul)** 키워드(금지구역·출입통제·수상레저·습지·해수욕장 등) → 본문 필터 → `notices_api.jsonl` 재생성
- 조례 보강: 기존 수집이 못 잡던 '낚시·금지구역·차박·글램핑' 조례 중 캠핑 관련만 추가
- **자동화**: 주 1회 재실행 권장(Tier 2, festival과 동일 주기). 새 고시·개정이 자동 반영됨
- 한계: **지자체 고시**(시군 홈페이지 게시판)는 API 미제공 → 데모 지역만 수동(`notices.jsonl`, 템플릿 `collect_notices_template.md`)
