# 🏕️ 차박·캠핑 편의시설 지도 — 팀원 모집 & 프로젝트 소개

> **한 줄 소개**: 지도에서 원하는 곳을 찍거나 채팅으로 물어보면, 주변 화장실·야영장·해수욕장·주차장과 개방시간·날씨·안전정보를 알려주고, AI가 "여기 근처가 차박하기 좋겠어요"라고 추천해주는 서비스.

- **마감/발표**: 교육과정 최종 프로젝트 (팀 진행)
- **인원**: 리더 1 + 팀원 1~2명 모집
- **현재 상태**: ✅ **동작하는 데모 이미 완성** (지도·마커·로드뷰 작동). 데이터·백엔드·프론트 뼈대까지 구축 완료 — 올라타서 함께 완성하면 됩니다.

---

## 1. 이 프로젝트에 합류하면 좋은 이유

- **이미 굴러가는 프로젝트** — 맨땅에서 시작이 아니라, 작동하는 코드 위에서 기능을 붙입니다.
- **진짜 공공데이터 + 실서비스 배포** — 전국 화장실 6만 개, 야영장 3천 개를 실제로 다룹니다.
- **요즘 뜨는 기술 풀스택 경험**: `GCP(BigQuery/Cloud Run)` + `RAG(검색증강생성)` + `카카오맵/로드뷰` + `FastAPI`
- **포트폴리오로 강함** — "공공데이터로 실배포한 AI 지도 서비스"는 이력서에 그대로 쓸 수 있습니다.

---

## 2. 서비스 개요 — 두 가지 사용 방식

### 🗺️ 모드 1. 지도 탐색
카카오맵을 확대/축소하며 주변 시설을 눈으로 확인. 마커를 누르면 이름·개방시간·시설 정보가 뜨고,
**로드뷰**로 실제 현장을 둘러보며 "여기면 차박 가능하겠다"를 직접 판단.

### 💬 모드 2. 대화형 추천 (AI)
> "7월 9일 서귀포 가는데, 바다 보이고 화장실 가까운 조용한 차박지 있어?"

이렇게 물으면 AI가 데이터를 검색해 야영장을 추천하거나, **우회적으로** "이 주차장이 화장실과 가까워요"라고 안내.
해수욕장이면 **만조·파고·날씨**를 보고 방문 타이밍까지 제안.

### ⚠️ 서비스 포지셔닝 (중요)
"불법 노지 캠핑을 조장"하는 게 아니라, **"사용자가 고른 지점의 공공 편의시설 정보를 제공"**하는 서비스.
합법 야영장을 함께 보여주고, 공영주차장은 차박을 권하지 않고 정보만 제공 → 발표 방어 논리로도 설계됨.

## 3. RAG를 어떻게 활용하는가 (프로젝트 핵심 요구사항)

**RAG(검색증강생성)** = LLM이 답하기 전에 우리가 준비한 문서를 검색해서, 그 근거를 바탕으로 답하는 방식.
단순 챗봇과 달리 **"우리 데이터에 근거한" 신뢰할 수 있는 답변**을 만듭니다.

### 지식베이스 2종
| 지식베이스 | 내용 | 왜 RAG가 필요한가 |
|---|---|---|
| ① **캠핑 규정·법령** | 하천법·해수욕장법·자연공원법 발췌, 지자체 차박금지 공고, 안전수칙 | 비정형 문서라 SQL로 못 다룸. "여기서 취사 돼?"에 **법령 근거를 인용**해 답변 |
| ② **야영장 소개문** | 이미 수집한 전국 야영장 3,023곳의 소개·시설 텍스트 | "오션뷰에 조용하고 반려견 되는 곳" 같은 **의미 검색** — 키워드 검색으로는 불가능 |

### 챗봇 처리 흐름
```
사용자 질문
   ├─▶ [정형 검색]  위치·거리 (SQLite / BigQuery GIS)
   └─▶ [RAG 검색]   규정·소개문에서 의미적으로 유사한 문서 추출
                        ↓
              LLM(GPT mini)이 두 결과를 근거로 인용하며 답변 생성
```

**발표 임팩트**: "이 서비스가 왜 ChatGPT와 다른가?" → 전국 실시간 시설 데이터 + 법령 근거 RAG = ChatGPT엔 없는 것.

## 4. 전체 아키텍처

```
[데이터 파이프라인]
공공 API(화장실/야영장/해수욕장) ──수집──▶ GCS(원본) ──▶ BigQuery(GEOGRAPHY, GIS 근접도 연산)
                                                                │
                                                    ┌───────────┴──────────┐
                                                    ▼(빠른 서빙)           ▼(RAG)
                                              SQLite(bbox 조회)      벡터DB(FAISS, 문서 임베딩)
[서빙]
프론트(HTML/JS + 카카오맵·로드뷰) ──REST──▶ FastAPI (Cloud Run 배포)
   ├─ 지도 탐색 ──▶ /api/facilities   (화면 영역 내 시설, SQLite)
   ├─ 대화형 추천 ▶ /api/chat         (정형검색 + RAG + GPT mini)
   └─ 방문 타이밍 ▶ /api/beach-timing (기상청 만조·파고·수온)
```

### 기술 스택
| 영역 | 기술 |
|---|---|
| 데이터 | 공공데이터포털 API, 카카오 지오코딩, BigQuery GIS |
| 백엔드 | Python, FastAPI |
| 프론트 | HTML/JS, 카카오맵 JavaScript SDK (지도·마커·로드뷰) |
| AI | RAG (sentence-transformers 임베딩 + FAISS) + GPT mini |
| 인프라 | GCP: GCS · BigQuery · Cloud Run · Cloud Build · Artifact Registry |

## 6. 🚧 남은 작업 (팀원이 맡을 부분)

| # | 작업 | 난이도 | 설명 |
|---|---|---|---|
| A | **RAG 파이프라인** | ★★★ | 규정·소개문 지식베이스 구축 → 임베딩 → 검색. GPT mini 키 연결(수요일 도착) |
| B | **대화형 추천 백엔드** (`/api/chat`) | ★★★ | 질문 파싱 → 데이터+RAG 검색 → 답변 생성 |
| C | **BigQuery GIS 적재·근접도 연산** | ★★ | 시설간 거리(해변↔화장실↔주차장) 전처리 |

| E | **Cloud Run 배포 + CI/CD** | ★★ | Docker → Cloud Build → 자동 배포 |
| F | **UI 다듬기 / 모바일(PWA)** | ★ | 반응형, 홈화면 설치형 앱 |

### 제주 특화 = 발표 하이라이트
발표는 "**제주 한정**"으로 하되 시스템은 전국 대응. 제주는 도정 오픈데이터가 풍부해서
**월파 CCTV로 해변 파도 위험 실시간 확인** 같은 "차박 안전" 킬러 기능을 얹을 수 있음.
