# 추천 점수화 + 질문 학습 파이프라인 설계

> 2026-07-06 구체화. 목표: "제주 서귀포시에 차박하기 좋은 곳? 전기차야" 같은 질문에
> GPT가 **감으로 답하지 않고, 우리 데이터로 계산한 점수를 근거로** 답하게 한다.
> 그리고 사용자 질문·반응을 로그로 쌓아 **주간 배치로 추천 품질을 개선**한다 (GPT 재학습 아님).

---

## 1. 전체 흐름

```
[실시간 — 질문마다]
사용자 질문 ─▶ ①조건 파싱 ─▶ ②후보 생성 ─▶ ③점수화 ─▶ ④RAG 근거 ─▶ ⑤GPT 답변 + 지도 핀
              (GPT mini)    (주차장·야영장) (SQL 근접연산)  (규정·소개문)   (점수 근거 인용)
                                                  ▲
[주간 배치 — 학습 루프]                            │ 가중치 갱신
대화 로그(chat_logs) ─▶ 주간 분석 배치 ─▶ ┬ 점수 가중치 튜닝
                                        ├ 자주 묻는 질문 → RAG 지식베이스 추가
                                        └ 파싱 실패 단어 → 조건 사전 갱신
```

**핵심 원칙**: "학습"은 GPT 파인튜닝이 아니라 ①점수 가중치 ②지식베이스 ③파서 사전을
데이터로 갱신하는 것. 강의 MLOps 그림의 **모니터링→피드백 루프**에 정확히 대응 (발표 포인트).

---

## 2. ① 조건 파싱 (팀원 B·C)

질문에서 구조화 조건 추출 — GPT mini function-calling 1회 (또는 키 전 정규식 폴백):

```json
{"region": "서귀포시", "date": "2026-07-09", "ev": true,
 "view": ["바다"], "quiet": true, "with": null}
```

- 인식 실패 단어는 `chat_logs.unparsed`에 기록 → 주간 배치가 사전 후보 리포트

## 3. ② 후보 생성

차박 후보 = **주차 가능한 지점**. 후보군 3종:

| 후보군 | 데이터 | 상태 |
|---|---|---|
| 공영주차장 | ⚠️ **공백 — 제주 주차장 API 재수집 필요** (아래 6절) | 최우선 액션 |
| 야영장 (합법 대안) | camping 3,023 (제주 45) + **loc_type 입지** | ✅ 준비됨 |
| 둔치주차장 | parking 322 (침수등급) — 제주 1곳뿐, 육지용 | ✅ 준비됨 |

region bbox 안의 후보만 (기본 반경 10km, 없으면 확장).

## 4. ③ 점수화 (팀원 C) — 차박 적합도 0~100

**정적 점수는 배치 사전계산** (후보×시설 근접 조인 — BigQuery GIS `ST_DWITHIN` 사용하면
강의 커버리지도 확보), **동적 점수는 서빙 시 가산**. 초기 가중치:

| 항목 | 계산 | 점수(초기 가중치) |
|---|---|---|
| 🚻 화장실 근접 | 최근접 거리 | ≤150m +20 / ≤300m +15 / ≤500m +8 |
| 🕒 화장실 개방 | open_hours가 24시간·상시 | +5 |
| 🌊 뷰(바다) | 최근접 해수욕장 | ≤500m +15 / ≤1km +10 |
| 🏞️ 뷰(계곡·숲) | camping loc_type에 계곡/숲/호수 | 질문 view와 일치 시 +15 |
| ⚡ 전기차 (조건부) | 질문 ev=true일 때만: EV충전소 ≤1km | +15, 실시간 급속>0이면 +5 |
| ⚠️ 침수 안전 | 둔치 위험등급 1/2등급 | −20 / −10 (호우예보 시 하천·해안변 −15) |
| 📹 안전 CCTV | ≤500m | +3 |
| 💊 심야약국 | ≤3km | +3 |
| ♻️ 클린하우스 | ≤500m | +2 |
| 🎉 혼잡 회피 | **개최기간 중**인 축제 ≤1km (festival, 전국문화축제표준 — extra.start/end 필드) | −8 (답변에 "붐빔" 안내) |
| 🧒 아이 동반 (조건부) | 질문 kids=true: 테마파크 ≤5km (`data/raw/theme_park.jsonl`) | +5, 답변에 "주변 놀거리" 소개 |
| ⭐ 인기 보정 | 피드백 루프 산출물 (5절) | +0~10 |

거리: SQLite는 하버사인 근사(위도당 111km), 배치는 BigQuery GIS. 가중치는
`data/score_weights.json` 파일로 분리 → 주간 배치가 갱신, 서버는 로드만.

## 5. 학습(피드백) 루프 — 주간 배치 (팀원 B·C, 배치는 D 스케줄)

**수집** — `chat_logs` 테이블 (SQLite, PII 없음·세션ID 익명):

```sql
CREATE TABLE chat_logs (
  ts TEXT, session TEXT,            -- 익명 세션 id
  question TEXT, parsed TEXT,       -- 원문 + 파싱된 조건(json)
  unparsed TEXT,                    -- 인식 못 한 표현
  results TEXT,                     -- 추천 후보 상위 N(id, 점수)
  clicked TEXT, feedback INTEGER    -- 클릭한 마커 id / 👍+1 👎-1
);
```

**주간 배치 `learn_weekly.py`** 산출물 3가지:
1. **가중치 튜닝**: 조건별 클릭률 분석 → `score_weights.json` 갱신
   (예: ev=true 질문에서 EV 근접 후보 클릭률 높음 → EV 가중치 15→18)
2. **인기 보정**: 클릭·👍 많은 장소에 `popularity` 점수 (+0~10, 상한 고정)
3. **지식베이스 성장**: 자주 나온 질문-답변 쌍 임베딩 → FAISS 추가
   (다음 유사 질문에 RAG 근거로 재활용), 파싱 실패 단어 리포트 → 조건 사전 갱신

⚠️ 답변 로그를 그대로 학습에 쓰면 GPT 오류가 증폭되므로, **사용자 긍정 반응(클릭·👍)이
있는 쌍만** 지식베이스에 넣는다.

## 7. ⑤ GPT 답변 형식 (팀원 B)

점수 상위 3곳 + 근거를 넘기면 GPT가 답변 생성. 프롬프트 규칙:
- 반드시 전달받은 점수·거리 데이터만 인용 (환각 방지)
- 프레이밍: 공영주차장에 "차박하세요" ❌ → "주차+화장실 가까운 지점" 우회 표현
- 응답에 후보 id 포함 → 프론트가 지도에 핀 + 클릭 로그 연결
